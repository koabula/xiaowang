# 05. 双手：文献、资料库、浏览器与执行

小王的「手」负责把课题做到对话以外：找到论文、打开网页、留下文件、必要时跑一段代码。这里记录的是边界。工具怎么命名、面板用哪种嵌入方式、搜索接哪一家，实现时可以用更简单的做法替换。

---

## 一、 文献不是某一个数据库

阶段一的 arXiv 适配只是第一家来源：公开接口、不必配密钥、结果结构稳定。它覆盖的是一部分预印本，主要在计算机、物理、数学这一带。

模型面对的能力是「找这篇作品」和「打开这个页面」。来源可以逐步加上更宽的元数据（如 OpenAlex、Crossref、PubMed）、用户资料库里的 PDF，以及网页。中文期刊和不少付费全文不在 arXiv 里，常常要登录之后用浏览器打开。

某个来源没有命中，就告诉用户这个来源没有，再换一条路。摘要和页面里没有的数字、题名、作者，不补。

---

## 二、 资料库与工作区

- **资料库**保存用户上传的，以及浏览器下载的原件。同一份内容只放一份。Bot 通过引用使用它。
- **工作区**保存这个 Bot 写出来的笔记、脚本和导出物。
- 上传和下载默认只给当前 Bot 引用。用户可以把同一份原件再交给另一个 Bot。
- 没有引用的 Bot 读不到该原件。删除 Bot 时，仍被引用的原件留在资料库。

---

## 三、 快捷搜索与应用内浏览器

两件事分开。快捷搜索回答「有哪些链接、最近发生了什么」，返回题名、摘要和地址，不打开窗口。浏览器负责点进去之后的事。

浏览器嵌在桌面应用内部，所有 Bot 共用这一份登录状态，不另运行一个外部浏览器。产品形态参考 Codex / ChatGPT 桌面版：你和代理看同一块页面，下载是正常使用的一部分，敏感动作先确认。操作方式参考 Claude Code 连接浏览器时的习惯：先看页面上有什么可点的，再点击、输入、滚动；登录和验证码交给人；页面上的文字不当成新指令。Claude Code 那条连到用户已打开的 Chrome 的进程链不必照搬，因为小王自己就是桌面应用。

使用上和人一样：打开地址、前进后退、标签、点击、输入、滚动、等待加载、下载。人和小王操作同一块面板。密码在页面里输入。付款、提交、删除账号数据之前停下来等用户。

同一时刻只有当前 Bot 驾驶。正文进它的会话；下载的文件进资料库，并挂到这个 Bot。其他 Bot 仍可使用快捷搜索。

面板放在哪、一次给模型看页面结构还是画面、下载要不要再问一句，实现时按手感调整。守住的是：在应用里面、共用登录、像人一样能点能下、课题之间不自动共享这次阅读。

---

## 四、 跑命令的两扇门

阶段一还没有终端。以后若要跑代码，分成两种授权，而不是一个能走进用户主目录的 shell。

- **工作区沙盒**：命令只看见当前 Bot 的工作区，有时间及输出上限。环境里不放模型密钥和浏览器登录。
- **用户授权的目录**：在界面里为这个 Bot 指定一个文件夹，可以取消。编辑和命令留在这个根目录里。不默认放开整个主目录。

资料库里的原件以阅读为主。要改、要分析时，把需要的材料引进工作区，或只读打开。网页和 PDF 里夹带的指令，不能借此碰到钥匙串或其他 Bot。

这两扇门等真的有脚本要跑，并且桌面端能让用户看清授权时再加。在此之前，列目录、读、写、检索文献、记术语、建立新 Bot，已经够命令行里的小王工作。

---

## 五、 现在先不钉死的选择

- 文献是一个入口还是按来源分几个动作。
- 快捷搜索用哪家服务；密钥与模型密钥一样，在设置里填写。
- 浏览器面板如何嵌进应用、小王如何驱动它（看结构、看画面，或两者都要）。
- 资料库如何去重、引用存在哪张表或哪个目录。
- 沙盒用进程隔离、容器，还是仅仅限制工作目录。

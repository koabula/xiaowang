# 01. 核心设计哲学与工程原则

在构建「小王同学」之前，我们先确立“什么该做厚，什么该做薄”。模型的原生能力正在快速迭代，今天为了弥补某一代模型缺陷而堆砌的复杂脚手架，明天可能就会变成拖累系统的历史包袱。

我们的架构建立在以下五条核心哲学之上：

---

## 一、 内循环极简且透明，拒绝黑盒重框架

> *"It’s an LLM, a loop, and enough tokens. The rest? Practical engineering and elbow grease."* — Thorsten Ball (*How to Build an Agent*)

- **直接掌控控制流**：后台 Agent 的核心本质就是一个清晰的推理与工具调用循环。我们倾向于直接使用薄封装的多模型 API 与自己编写的轻量控制循环（Harness），而不是引入层层抽象、掩盖底层 Prompt 与消息结构的重型编排框架。
- **按需增加复杂度**：遵循 *Building Effective Agents* 的原则——能用单次检索或简单工具调用解决的日常指令，绝不强行走多智能体编排；只有面对真正的重度科研任务（如多篇论文并行精读核验、多源交叉对比）时，才动态派生 Worker 子任务。

---

## 二、 Session 不是某一个模型的 Context Window

> *"The session is not the context window."* — Anthropic (*Scaling Managed Agents*)

这是实现 **「Realtime 语音模型与后台 LLM 共享统一连续身份」** 的最关键抽象：

- **持久化事件源唯一**：系统的真实记忆不活在某条 WebSocket 连接里，也不活在某次 LLM 请求的 `messages` 数组里，而是活在一个独立、持久化的会话记录（Session Log）中。
- **上下文只是按需投影（Projection）**：
  - 当后台 LLM 工作时，Harness 从 Session 中投影出**高信息密度的富文本上下文**（包含完整文献细节、代码、工具返回与直接打字记录）。
  - 当前台 Realtime 模型通话时，桥接层从同一个 Session 中投影出**轻量、口语化的上下文快照**（项目基线、近期结论摘要、在途任务与课题专有术语）。
- **裁剪对用户不可见**：窗口装不下时，可以少拿一些较早的轮次，或在这一次请求里用摘要代替更早的原文。用户感受到的仍是同一个小王还记着前面的事。小王不宣布「我压缩了上下文」，也不把投影、后台、工具这些机制说出来。需要旧细节时，自己回读会话或笔记，然后照常接着说。
- **结论落在笔记里**：已经确认的出处、数字和边界写进当前 Bot 的笔记。摘要和裁剪最容易丢掉的就是这些。笔记还在，人就还在。
- **可恢复与可替换**：因为状态在 Session 里而非模型连接里，无论是网络断线重连、通话挂断切回文字输入，还是中途把语音引擎从 `MOSS-Live` 换成 `Qwen3.5-Omni`，Agent 的记忆与身份都不会断裂。原文不因某次投影被盖掉，所以以后仍可按记录回读。

---

## 三、 大脑（Brain）与双手（Hands）及凭据解耦

- **无状态的推理层（Cattle, not Pets）**：无论是后台 LLM Harness 还是前台 Realtime 会话，都应当是随时可以销毁和唤醒的“无状态工人”。某次工具崩溃或某条语音流异常，不应破坏项目空间本身的数据完整性。
- **安全与凭据边界**：科研与日常助手会连接模型服务、搜索服务，以及 Zotero、网盘、邮箱、日历等个人服务。桌面端由用户在设置里填写这些密钥，存入系统保护的凭据层（如系统钥匙串）；命令行阶段可以用环境变量。产品不以仓库里的 `.env` 作为密钥柜。密钥不进入会话、工作区、模型上下文，也不进入跑代码的环境。界面上只需让用户知道「已保存」以及足够核对的末几位。

---

## 四、 像打磨 UI 一样打磨 ACI（Agent-Computer Interface）

我们花多少心思设计给人类看的桌面界面（HCI），就应该花同等的心思设计给模型用的工具接口（ACI）：

- **对前台实时模型做减法**：全双工语音模型对延迟极其敏感。不要把几十个细粒度的外部工具直接塞给 Realtime 模型，而是只给它极少数语义极其清晰的“协同元工具”（如派发任务、查进度、修改/取消任务），把复杂的工具选择留给后台慢思考的 LLM。
- **防呆设计（Poka-yoke）**：工具的参数命名、边界说明、报错提示都应像写给团队新人的高质量文档一样直白，从接口形态上减少模型犯错的可能（例如明确的工作区路径约束、让错误返回值自带修复线索以便模型自愈）。
- **网页是资料**：浏览器里读到的正文、按钮文字和论文页面，是待核对的材料，不是给小王的新指令。

---

## 五、 模态各司其职：听觉重交互节奏，视觉重高密度交付

科研辅助与纯闲聊助手最大的不同在于**产物的复杂度**：

- **语音通道（Realtime）** 负责自然倾听、随时可打断的讨论、意图澄清、情绪陪伴，以及用几句话讲清核心结论。它绝不应该去逐字朗读 URL、Markdown 符号、LaTeX 公式或大段表格。
- **工作台通道（Workspace UI + LLM）** 负责承载严谨的文献核验笔记、方法对照清单、代码片段与打包好的附件。
- 两路通道实时联动——“嘴上聊着思路，手头屏幕上同步跳出整理好的资料”，才是科研与日常双栖助手的最佳形态。

---

## 六、 隔离话题，共享用户明确交出的东西

Bot 之间隔开的是会话、笔记和结论，以免课题互相污染。可以共用的，是用户明确交出来的东西：

- 资料库里的论文原件、应用内浏览器的登录状态、已经连接的外部应用，是全局的。
- 一次阅读或一次下载归当时正在用的那个 Bot。另一个 Bot 要用同一份原件，等用户说一声再给引用。
- 跑命令如果发生，也只发生在这个 Bot 的工作区，或用户为它指定的目录里。不默认放开整个主目录。

交互与研究有不同的时间要求

一次语音回应需要尽快开始，一次研究可能涉及多轮检索、阅读和工具调用。用户还会在工作进行中补充要求、打断讲解或切换资料。小王将实时对话和研究执行分别交给 Realtime 与后台 LLM，通过应用层连接两条流程。

模型负责理解请求、生成内容和选择工具。应用保存任务与历史，执行工具，协调音频播放和页面展示，并根据执行结果安排下一步。

系统协作

两类模型如何协作

Realtime 接收语音并生成回应，可以直接调用读取资料、翻页和展示工具。需要多步处理的研究通过 delegate_task 交给后台 LLM，通话继续接收用户输入。后台将执行进度和结果回传到通话上下文。

任务连接两个模型

语音委派进入 JobQueue，获得本地任务编号。进度与结果持久化后更新到 Realtime。需要口头汇报时，通话适配器等待用户与播放状态允许，再发出通知。notify=silent 控制静默完成。

应用保存执行归属

bot 标识确定任务使用哪份会话、资料与工作区，originCallId 关联发起委派的通话。挂断后，已受理的任务可以继续完成，结果仍归属原通话。

执行机制

一次任务如何执行

任务从已保存的用户请求开始。每一步装配上下文并调用 LLM，模型返回工具调用时，应用执行工具、保存结果，再进入下一次调用。模型返回普通答案后，循环检查还有没有待处理的补充，再决定是否完成。

何时接收新要求

执行中的普通消息默认补充当前任务。消息保存后，readUpdates() 在下一次模型调用前取出尚未接收的补充，连续多条一起合入。正在运行的工具先返回，模型随后根据新要求调整工作。

何时结束当前任务

一次回复生成期间仍可能收到消息。普通答案返回后，有新补充就保留当前输出并继续处理。无工具调用且没有待处理补充时，确认最终回复，回写任务终态并释放执行槽位。

同一 bot 串行执行，默认最多两个工作区并发。显式“排队新任务”或 mode=queue 创建独立任务。停止操作通过 AbortSignal 传入支持取消的执行路径。桌面任务最多进行 40 步模型调用，达到上限后保留已有输出，供检查与重试。

文字与语音补充复用同一队列。语音侧由转写识别或 Realtime 工具调用受理，Gemini 的首次研究委派通过工具发起。同一发言关联同一个任务编号，来源标识用于去重，防止重复启动。

上下文策略

模型每次看到什么

模型输入由人设与任务说明、会话投影、资料引用和当前工作区状态组成。后台 LLM 使用会话与工具结果推进研究。Realtime 开通话时接收近期对话简报，通话中持续接收页面、任务和结果更新。

任务上下文的接收时机

任务在受理时复制工作区快照。单纯浏览另一页会更新通话的可见页面上下文。给任务追加消息时，任务接收该补充关联的新快照和匹配的页面画面。下一次调用据此更新上下文。

图像与 PDF 当前页

附件事件保存引用，调用后台模型前再加载图片字节。PDF 当前页渲染为图像。Gemini、OpenAI 和千问接收受控的视觉输入，画面队列以每秒最多一帧发送并淘汰过期页面。豆包当前通过后台模型处理图片与 PDF 分析。

可见页面由独立的 viewRevision 校验，任务进度更新使用工作区 revision。重启后恢复的页面先标记为隐藏，等待界面重新确认。浏览器页面由模型通过浏览工具访问。当前视觉共享路径覆盖已发送图片以及右侧图片、PDF 当前页。

Realtime 与共享快照的有界参数
内容当前策略
Realtime 初始简报最近 6 段对话，每段按 180 字符截短；目标按 500 字符截短，附带术语与最近 8 个产物路径。
资料目录最多列出 40 项，再通过 list_library 与阅读工具获取内容。

这些参数控制通话简报与共享状态。后台 LLM 使用下述 token 预算与确定性重投影。Gemini Live 还启用服务端 slidingWindow 上下文压缩，其内部 token 与缓存不进入后台模型统计。

请求组成

从稳定规则到最新要求

每次后台请求包含稳定的 system 与 tools，以及从事件生成的 messages。消息包含选中的历史单元、任务与工作区快照，以及本轮用户要求和连续补充。旧历史归档后，输入还会带上事件范围和反查入口。

固定规则、工具定义和预算保存为 context_scope；任务受理或收到补充时的背景保存为 context_state。投影清单引用这些事件，图片附件在发送前加载原件，文档正文由工具按页读取。

同一周期沿用已有消息顺序并追加尾部。任务说明、术语、目录和页面状态变化时追加新证据，重投影保留每个状态键的最新准确值。后台历史范围由预算与任务归属决定。

事件与输入

投影如何产生

projectContextUnits 将事件转成完整消息单元，采用指定的语音修订，关联助手调用与工具结果。新执行使用应用生成的调用编号和 assistantEventId 记录归属，旧日志按最近的对应调用配对。

context_append 保存来源编号和渲染方式。renderEntry 从这些精确来源恢复消息，迟到修订追加更新说明。任务调用前装配图像并检查预算，准备期间到达的补充再次合入后才发起推理。

投影器不调用模型或重跑工具。相同事件、版本、预算和原件得到相同视图。页面帧只在当前进程内可用，状态文字始终说明其可用范围；图片附件可以按引用恢复。旧字符裁剪函数保留作兼容用途，正常任务走新管理器。

协议与恢复

Thinking 数据如何回到模型

正文和协议分别保存。OpenAI 兼容接口接收 reasoning_content / reasoning_details；Anthropic 保存完整内容块，包括 thinking、签名和 redacted thinking。流式分片组装后写入 assistant_turn.protocol，关联接口与模型身份。

同模型从原事件恢复协议块，调用与结果保持成组，使用服务商原始工具编号和参数回传。协议参与输入预算，输出预留包含 thinking；thinking 不作为聊天正文或历史搜索内容。

旧版本缺少所需字段、模型或接口不同、输出额度耗尽时，整组转为明确标注的历史数据，沿用已记录结果，不补造 reasoning，不重新执行已完成的工具。输出达到 length / max_tokens 时记录协议与用量，报告未完成，本步工具不执行。

投影版本 2 从原事件重建清单，版本 1 清单保留。原生协议块完整保留或整组归档，不做局部摘录。

前缀与缓存

为什么已有块保持不变

正常调用在尾部追加消息，固定指令与工具定义保持稳定，适配器保留用户消息块边界。目录变化与转写修订以新块表达。超过水位时，程序一次性重建投影视图并递增 epoch。

保留前缀复用机会

官方 OpenAI 请求带作用域与周期派生的 prompt_cache_key，Anthropic 启用自动 cache_control。可用 XIAOWANG_PROMPT_CACHE=off 关闭可选缓存字段。实际命中由服务端决定。

记录实际用量

model_usage 保存请求哈希、完整预算、耗时与服务端用量。prefixTokens 是共同前缀的本地估算，未报告的实际用量显示 null。

npm run xiaowang -- stats [slug] 汇总调用、检查点及实际 token 用量。缓存读取比例只使用同时报告输入与缓存读取的调用。重启后恢复事件投影，共同前缀诊断从 0 开始。

预算与选择

为整个请求留出空间

后台研究与 Realtime 通话使用独立预算。设置 → 文字 → 研究上下文预算可选择保守档或研究档，分别配置总窗口、输入高低水位、输出和安全预留。模型窗口上限由服务商能力决定，填入后约束实际应用窗口；未知模型默认使用保守档。

怎样计数

文本以本地 o200k_base BPE 分段估算，增加 20% 余量与封装开销；图片每张预留 8,192 tokens。官方 Anthropic 使用原生计数覆盖总输入，分项仍为本地估算。实际用量按响应记录。

怎样重建

超过所选高水位时，以低水位为选择目标。保留当前任务的输入事件、连续补充、最新状态及最后一个对话单元；先移除被取代的旧状态，再折叠较早工具结果，最后优先归档已结束任务，其余按较旧单元顺序处理。

普通工具摘录保留前 1,200 字符和来源指针；旧 thinking / 签名单元和较大参数单元整体变为引用。归档只改变视图，原始事件保持完整。结果在硬预算内且确实缩小后，提交 context_checkpoint。必要内容较大时可以高于低水位；原生计数仍超限时再尝试归档全部可选历史。

检查点记录投影版本、截止事件、来源编号、渲染方式、状态引用和保护集合。取消或无法容纳当前输入时保留原投影，返回预算错误。上下文维护不产生自动 LLM 摘要调用。

记忆与反查

历史如何被再次使用

原始用户消息、模型回复、工具结果与语音修订保存在追加式事件中。模型通过 search_memory 找到当前 bot 的相关记录，再用 inspect_event 按编号读取原文，读取历史不会重新执行工具。

找到原始记录

SQLite FTS5 trigram 索引支持中文子串，少于 3 个字符时使用字面查询。关键词按字面处理，可筛选事件类型，通过 after_id 分页，每页最多 20 条。派生投影和用量记录不进入模型历史检索。

按需展开证据

inspect_event 使用事件编号、字符偏移与页长，默认读取 4,000 字符、最多 6,000，并返回下一偏移量。查询与读取均限定当前 bot，资料原件仍通过文件与阅读工具访问。

任务与工作区快照保存受理时的准确值。用户要求保存的笔记与结论是普通工作产物。bot 元数据和资料引用仍有各自状态表；这里实现的是上下文的事件投影与恢复，所有界面操作尚不能由事件流重放。

资料原件按 SHA-256 去重，图片与 PDF 保存引用，投影检查点保存来源清单。备份需同时包含数据库、资料库与工作区。临时页面像素和音频队列只在当前进程内保留。

实时交互

通话如何保持连贯

模型生成结束后，音频可能仍在传输或排队播放。用户实际听到的位置由渲染进程的播放器确认。播放位置、片段完成与空闲回执返回调度层，用于协调插话、连续讲解和挂断。

插话

用户发言会停止匹配的本地音频，拒收已被中断回复的迟到数据。后台研究保留自己的任务生命周期，继续执行。

连续讲解

应用保留讲解目标、材料、页码和暂停状态。Gemini 在生成与实际播放结束后，通过资料展示回执推进页码，再请求下一段讲解。其他适配器保留各自的兼容调度方式。

结果通知与结束

后台结果先进入任务记录，再根据通知设置、用户发言与播放状态安排口头汇报。自然挂断要求用户有明确意图，并等待道别的实际播放完成。

工作区与工具

工作区如何隔离

spawn_bot 接收新 bot 的任务说明、术语、所需资料和首轮要求。工具会先解析文件引用，再建立 bot 并交接原件引用。父轮成功完成后，待启动的子任务才进入队列。子 bot 从自己的任务说明、会话与资料目录开始工作。

每个 bot 拥有独立的浏览页面、导航历史与控制权，底层共用 persist:xiaowang 持久化 Session。共享登录状态让不同课题可以使用同一份网站登录资料。用户取得页面控制权后，浏览器输入守卫和模型工具侧都会校验当前操作者。

获取与阅读

search_literature 检索文献，浏览器工具获取网页和原文，read_document 按页或行读取资料。

保存与交接

write_file 保存产物，import_file 导入资料，share_file 交接引用，remember_terms 保存术语。

展示与协作

show_stage 打开 PDF、浏览器或 HTML Canvas，并返回展示回执。spawn_bot 建立独立课题。

Canvas 通过 data-xw-slide 标记页面，active 标记当前页，也可以暴露 window.xiaowangSlides 导航接口。主进程发起展示请求，界面确认实际页码后返回回执，讲解流程再据此继续。

执行可靠性

任务如何恢复

本地任务恢复

队列从事件恢复最新任务状态。排队任务可以继续执行，应用关闭时仍在运行的任务恢复为 interrupted。用户检查已有产物后可以手动重试，关联的补充消息和附件引用继续保留。

通话连接恢复

Gemini 恢复句柄保存在进程内，短时断线复用远端会话，并去重重放的工具调用。断线期间的语音由用户重述。挂断后，已经受理的后台任务继续运行，结果保留在原通话记录。

工具返回的 isError 会作为工具结果交回模型，供下一步调整。模型请求失败等抛出的异常由队列记录为 failed，已保存的事件和产物可供检查与重试。
